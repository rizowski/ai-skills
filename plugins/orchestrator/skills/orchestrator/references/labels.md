# Labeling replies

Read this before you choose the labels of a session.

When more than one priority is active, start every reply, and every topic section inside
a reply, with a bold bracket label that names the task, inline with the first sentence.
For example: `**[LABOR]** Phase 4, step 3 of 5.`

- A label is a short uppercase name, one per priority. Choose it once and keep it for the
  session. Record it on the priority's line in the priorities file, so a label maps to its
  task ids.
- Use no emoji, no symbols, no code style and no color. Terminal markdown cannot color
  text, and code style draws every label the same.
- Never write a line such as "Nothing new from that notice" without a label. Say which
  task a notice or a worker report belongs to.
- A reply about the orchestrator itself uses `**[ORCHESTRATOR]**`.
- Labels are shorthand between you and me, so either of us can name a task quickly. They
  mean nothing to other readers, so never write a label into a tracker task title,
  description or comment, or anywhere else that other people read. When I use a label,
  look it up in the priorities file to find the task.
